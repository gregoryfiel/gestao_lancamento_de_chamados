## Goal for this release line

Close **CRUD completeness** on the BFF with bulk import and stakeholder export,
and publish an explicit **BFF vs SPA** contract for the front-end agent.

---

## Source of truth

- [x] API + Unity Catalog Delta (`mrt_am_sit.gold_common.tickets` + `ticket_events`).
- [ ] Excel / SharePoint as ledger — **not** used; export is a read-only view.

---

## Contract (delivered on ADO)

- `POST /api/v1/tickets:bulk-create` — up to 200 `TicketCreate` items; per-row `201`/`400`.
- `GET /api/v1/tickets/export` — `format=xlsx|csv`, list filters, `columns` whitelist, `max_rows` cap (100k).
- Existing CRUD unchanged: list/get/create/patch/delete/bulk-update/events.

Canonical consumer doc: [`docs/FRONTEND_API_CONTRACT.md`](../FRONTEND_API_CONTRACT.md) §2, §3, §11.

---

## Schema mapping (`TicketRead` export columns)

Default export order (override with `columns=`):

`ticket_id`, `status`, `priority`, `requester_email`, `employee_id`, `team`,
`role`, `require_system`, `summary`, `opened_on`, `submitted_at`, `updated_at`,
`jira_ticket` (derived from `reference_url`).

## Security & compliance

- Secrets: BEES SPN only on server; `openpyxl` added to `requirements.txt`.
- PII in logs: emails/employee ids may appear in export files — treat downloads as confidential.
- Audit trail: unchanged (`ticket_events`).
